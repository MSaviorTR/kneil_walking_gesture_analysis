### Checked and found correct
- `components/kneil_proto/kneil_proto.c` and `.h` are byte-identical (`fc.exe /b`) to `kneil_firmware/protocol/kneil_proto.c/.h`.
- `KNEIL_UUID_BASE_LE` and `kneil_uuid_le()` in `main/kneil_state.c:179-189` produce the exact little-endian bytes for `a8f5000X-3e2c-4c6e-9b1a-6b4e45494c00` (`0x0001` service, `0x0002` LIVE, `0x0004` CONTROL, `0x0005` INFO, `0x0006` SUMMARY) matching `kneil_firmware/protocol/README.md` and `kneil_live.c:206-211`.
- `ble_gattc_disc_all_dscs()` in `main/kneil_central.c:281-293` passes `start_handle = sub_value` (characteristic value handle) and `end_handle = next_def - 1` (or `svc_end`), matching `ble_gatt.h:664-667` and `ble_gattc.c:3264-3266` (`prev_handle = start_handle`, searches `prev_handle + 1 .. end_handle`), and `kneil_cccd_for()` filters by `[value + 1, end]` and picks the lowest CCCD (`0x2902`).
- Starting `ble_gattc_exchange_mtu()` immediately followed by `ble_gattc_disc_svc_by_uuid()` (`kneil_central.c:633-635`) is safe in ESP-IDF 6.1 NimBLE: `ble_att_tx_with_conn()` (`ble_att_cmd.c:90-99`) sets `conn->client_att_busy = true` on the MTU request and queues the service discovery request in `conn->att_tx_q` until the MTU response arrives, so MTU negotiation finishes before discovery/subscriptions (ensuring the implant's initial INFO burst and SUMMARY packet see MTU 247).
- `sdkconfig` has `CONFIG_BT_NIMBLE_ATT_PREFERRED_MTU=256`, `CONFIG_BT_NIMBLE_GATT_MAX_PROCS=4`, `CONFIG_BT_NIMBLE_MAX_CONNECTIONS=2`, and `CONFIG_BT_NIMBLE_HOST_TASK_STACK_SIZE=6144`, compatible with the implant's `CONFIG_BT_L2CAP_TX_MTU=247`, 41-byte SUMMARY (needs MTU >= 44), and 101-byte INFO packets.
- All NimBLE GATT callback signatures (`on_mtu`, `on_svc`, `on_chrs`, `on_sub_dsc`, `on_cccd_written`, `on_ctrl_written`) and return values (`0`) match `host/ble_gatt.h`; `BLE_HS_EDONE` and non-zero error statuses are handled cleanly (including `BLE_HS_ENOTCONN` from `ble_gattc_connection_broken()` on disconnect).
- `ble_gap_disc()` uses active scanning (`passive = 0`), which is required because `kneil_live.c:318-320` places the 128-bit service UUID in the scan response (`sd[]`) and `KNEIL-xxxx` in the advertising payload (`ad[]`).
- `ble_gap_disc_cancel_no_lock()` (`ble_gap.c:7097-7123`) does not emit `BLE_GAP_EVENT_DISC_COMPLETE`, so cancelling the scan in `scan_window_cb()` does not trigger a spurious `rescan_later()` from `BLE_GAP_EVENT_DISC_COMPLETE`.
- Implant connection parameter update requests (`CONFIG_BT_GAP_AUTO_UPDATE_CONN_PARAMS=y`, 100–200 ms interval in `kneil_firmware/prj.conf:45-49`) trigger `BLE_GAP_EVENT_CONN_UPDATE_REQ`; `gap_event()`'s `default: return 0;` causes `ble_gap.c:8938-8940` to accept the implant's preferred parameters cleanly.
- Notification handling (`handle_notify()`, `kneil_central.c:312-391`) checks `event->notify_rx.conn_handle == conn`, clamps `OS_MBUF_PKTLEN(om)` to `sizeof(buf)` (256 B), checks `ble_hs_mbuf_to_flat()` return value, routes strictly by discovered value handles (`h_live`, `h_summary`, `h_info`), decodes both v1 (20 B) and v2 (22 B) LIVE packets, and safely strips `"I,"` and `"\n"` from INFO lines (`n >= 4` on valid decode).
- `kneil_model_t` reads/writes (`set_link`, `on_live_decoded`, `on_summary_decoded`, `on_info_text`, `kneil_central_snapshot`) are serialised with `lock`, and `ble_service_start()` calls `kneil_central_set_active()` -> `ensure_init()` on `app_main` before `nimble_port_freertos_init()`, `ui_init()`, and `usb_console_start()` (`main.c:62-69`).
- Page 1 rebuild in `ui.c:134-199` runs solely on the LVGL thread (`sync_page1()` inside `refresh_cb()`), calls `ui_face_destroy()` + `lv_obj_clean(tile)` before recreating widgets, tracks `built_kneil` consistently so `ui_kneil_refresh()` never touches NULL or destroyed widgets, and handles `lv_tileview_get_tile_active(ui_tv) == NULL` before the first swipe (`ui.c:349-352`).
